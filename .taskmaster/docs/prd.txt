# PackageDSLKit - Product Requirements Document (PRD)

## Project Overview
PackageDSLKit is a Swift library and CLI tool for creating and manipulating Swift packages that use the PackageDSL library. It provides both a programmatic SDK and a command-line interface to make working with PackageDSL-based packages practical and efficient.

## Primary Goals
1. **Package Creation**: Easy initialization of new PackageDSL-based packages with templates
2. **Package Manipulation**: Add, remove, and modify targets, products, and dependencies in PackageDSL packages
3. **Developer Experience**: Provide both SDK and CLI interfaces for different use cases
4. **Swift Package Manager Integration**: Leverage `swift package` commands for metadata instead of parsing Swift files directly

## Core Features

### 1. Swift SDK (PackageDSLKit Library)
**Programmatic API for other tools and applications**

#### Package Management SDK
- `PackageDSLManager` - Core package manipulation APIs
  - Create new packages with specified types
  - Add/remove targets, products, and dependencies
  - Generate Package.swift from PackageDSL definitions
  - Validate package structure and consistency

#### Code Generation SDK  
- `DSLCodeGenerator` - PackageDSL code generation
  - Generate Target structs with appropriate protocols
  - Generate Product structs (library/executable)
  - Generate PackageDependency structs
  - Generate main Package() definition with result builders

#### File Management SDK
- `DSLFileManager` - File operations and organization
  - Create proper PackageDSL directory structure
  - Write and organize DSL component files
  - Manage source file layout and naming conventions

#### SPM Integration SDK
- `SPMIntegrator` - Swift Package Manager integration
  - Execute `swift package dump-package` for metadata
  - Parse SPM JSON output into structured data
  - Validate PackageDSL against actual SPM behavior

#### Swift Settings Management SDK  
- `SwiftSettingsManager` - Swift feature and flag management
  - Add/remove Swift feature flags (experimental/upcoming)
  - Add/remove unsafe flags (compilation, debug, emit, warning flags)
  - Handle parameterized flags (WarnLongFunctionBodies, etc.)
  - Target-specific Swift settings configuration

#### Platform Management SDK
- `PlatformManager` - Platform support management
  - Year-based platform sets (2019-2024 mapping to OS versions)
  - Individual platform specifications (iOS, macOS, watchOS, tvOS, Linux)
  - Custom platform set creation with include/exclude options
  - Platform version validation and consistency checking

### 2. CLI Tool (package executable)
**Command-line interface using ArgumentParser**

#### Package Lifecycle Commands
```bash
package init                                    # Initialize new PackageDSL package
package init --name MyLib --type library       # Create library package
package init --name MyApp --type executable    # Create executable package
package validate                                # Validate PackageDSL structure
package convert <Package.swift>                # Convert from traditional Package.swift
```

#### Component Management Commands
```bash

package target add <name> --type executable    # Add executable target

# Product Management

package product add <name> --targets t1,t2    # Specify target dependencies
package product remove <name>                 # Remove product
package product list                           # List all products

# Dependency Management
package dependency add <name> <url>           # Add URL dependency
package dependency add <name> <url> --version "1.0.0"    # Exact version
package dependency add <name> <url> --from "1.0.0"      # From version
package dependency add <name> --path "../Local"         # Local dependency
package dependency remove <name>              # Remove dependency
package dependency list                       # List all dependencies
```

## Technical Architecture

### Dual-Purpose Design
1. **Swift SDK** - Library for programmatic use by other tools
2. **CLI Tool** - ArgumentParser-based command interface

### Key Design Principles
- **SDK handles logic** - All business logic in the PackageDSLKit library
- **CLI handles interface** - ArgumentParser commands are thin wrappers around SDK
- **SPM Integration** - Use `swift package dump-package` instead of parsing Swift syntax
- **Clear separation** - SDK completely independent of CLI implementation

### Integration Strategy
- Leverage Swift Package Manager's built-in metadata capabilities
- Use `swift package dump-package` for authoritative package information  
- Focus on PackageDSL generation and manipulation rather than parsing
- Validate PackageDSL by comparing generated Package.swift with SPM metadata

## Implementation Phases

### Phase 1: Core SDK Foundation (HIGH PRIORITY)
- PackageDSLManager with basic CRUD operations
- DSLCodeGenerator for basic code generation
- DSLFileManager for file operations  
- SPMIntegrator for swift package commands
- Basic SwiftSettingsManager (common feature flags and unsafe flags)
- Basic PlatformManager (year-based platform sets)

### Phase 2: CLI Commands Implementation (HIGH PRIORITY)
- Update CLI main entry point with proper command structure
- Complete target, product, and dependency management commands
- Add Swift feature and unsafe flag management commands
- Add platform and platform-set management commands
- Add package generation and validation commands

### Phase 3: Advanced Configuration (MEDIUM PRIORITY)
- Complete SwiftSettingsManager (all unsafe flags, parameterized flags)
- Target-specific Swift settings management
- Custom platform set creation with include/exclude options
- Enhanced error handling and validation
- Implement conversion from traditional Package.swift

### Phase 4: Ecosystem Integration (LOW PRIORITY)
- IDE integration helpers
- CI/CD integration utilities
- Watch mode for development workflows
- Community template system

## Success Metrics
- Streamlined creation of new PackageDSL packages
- Easy management of existing PackageDSL packages  
- Generated PackageDSL produces identical Package.swift output
- Reduced complexity in PackageDSL package maintenance
- Active adoption by Swift package developers
- Comprehensive tooling ecosystem around PackageDSL

## Example Usage

### SDK Usage (Programmatic)
```swift
import PackageDSLKit

let manager = PackageDSLManager(at: URL(fileURLWithPath: "."))
try manager.createPackage(name: "MyLibrary", type: .library)
try manager.addTarget(name: "Core", type: .library) 
try manager.addProduct(name: "MyLibrary", targets: ["Core"])
try manager.addDependency(name: "Alamofire", url: "https://github.com/Alamofire/Alamofire.git", from: "5.8.0")
try manager.generatePackageSwift()
```

### CLI Usage (Command Line)
```bash
# Create and setup new package
package init MyLibrary --type library
package target add Core --type library
package product add MyLibrary --targets Core
package dependency add Alamofire https://github.com/Alamofire/Alamofire.git --from 5.8.0

# Generate and validate
package generate
package validate
```

### Proper Layered Architecture Examples

#### CLI Command (Only Calls SDK)
```swift
struct InfoCommand: ParsableCommand {
    @OptionGroup var settings: Settings
    
    func run() async throws {
        // CLI only talks to SDK, never directly to SwiftPackageManagerKit
        let manager = PackageDSLManager(at: settings.packagePath)
        
        // SDK handles all SPM integration internally
        let packageInfo = try await manager.getPackageInfo()
        
        // CLI formats the results from SDK
        let formatter = OutputFormatter()
        print(formatter.formatPackageInfo(packageInfo))
    }
}
```

#### SDK Implementation (Uses SwiftPackageManagerKit Internally)
```swift
public class PackageDSLManager {
    private let smpIntegrator: SPMIntegrator  // Internal use of SwiftPackageManagerKit
    
    public func getPackageInfo() async throws -> PackageInfo {
        // SDK uses SwiftPackageManagerKit internally
        let smpData = try await smpIntegrator.dumpPackage()
        let dslConfig = try parseCurrentPackageDSL()
        
        // SDK provides unified view to CLI
        return PackageInfo(
            smpData: smpData,
            dslConfiguration: dslConfig,
            validationResult: try validate(dsl: dslConfig, against: smpData)
        )
    }
}
```

#### Internal SPM Integration (Hidden from CLI)
```swift
internal class SPMIntegrator {
    private let executor: SPMExecutor  // Uses SwiftPackageManagerKit
    
    func dumpPackage() async throws -> SPMPackageInfo {
        return try await executor.dumpPackage(at: packagePath)
    }
}
```
